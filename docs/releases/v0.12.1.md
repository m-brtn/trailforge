Fix-only re-release of TrailForge v0.12.0, an off-road vehicle prototype on a small custom C++20 engine (SDL3 +
SDL GPU, Jolt Physics `WheeledVehicleController`, Dear ImGui, own audio mixer on miniaudio). The game is unchanged
from v0.12.0: levels and the open-world level **Exploration Peaks** (see the v0.12.0 notes).

**Platforms:**

| Package | Status |
|---|---|
| `TrailForge-0.12.1-macos-arm64.zip` | macOS 27 on Apple Silicon. **Run and verified** (built for macOS 27.0). |
| `TrailForge-0.12.1-windows-x64.zip` | **UNTESTED ON REAL HARDWARE.** Built and headless-tested in GitHub Actions (MSVC, x64); the D3D12 / Vulkan rendering has never been run. |
| `TrailForge-0.12.1-linux-x64.tar.gz` | **UNTESTED ON REAL HARDWARE.** Built and headless-tested in GitHub Actions (gcc, Ubuntu); the app was only started on Mesa lavapipe (software Vulkan) under Xvfb. |

## Fixes since v0.12.0

- **The Windows and Linux packages now contain the levels.** The v0.12.0 Windows and Linux packages were missing
  `assets/levels`, so their start menu offered only the Proving Ground. Both package scripts now copy the whole
  `assets` folder, as the macOS bundle already did. All three package scripts now fail if the Exploration Peaks
  definition is missing. The app now logs the levels it found; the macOS smoke tests and the CI lavapipe run check
  that line. The macOS v0.12.0 package was not affected.

## Controls

Unchanged from v0.12.0 (M: map on a level, R: reset to the nearest road on a level; full table in the README).

## How to open it

**macOS.** The app is **ad-hoc signed, not notarized**, so Gatekeeper blocks a plain double-click after downloading.

1. Unzip `TrailForge-0.12.1-macos-arm64.zip`.
2. Either right-click `TrailForge.app` → **Open** → **Open**, or remove the quarantine flag in Terminal:
   `xattr -dr com.apple.quarantine TrailForge.app`

**Windows (untested on real hardware).** Unzip, keep the `assets` folder next to `trailforge.exe`, run it. The exe
is not code-signed, so SmartScreen may warn ("More info" → "Run anyway"). Needs a Direct3D 12 or Vulkan GPU driver.

**Linux (untested on real hardware).** `tar xzf TrailForge-0.12.1-linux-x64.tar.gz`, then
`./TrailForge-0.12.1-linux-x64/trailforge`. Needs a Vulkan driver (Mesa RADV / ANV / NVK or the NVIDIA driver).

## Known limitations

As in v0.12.0: Windows and Linux have never been run on real hardware; water has no physics (deep water and the
map edge put the vehicle back on a road); snow is rigid low-grip ground; ground materials are procedural (PBR
textures are planned for v0.13.0); High drops to about 95 FPS looking across the lake; the macOS build is not
notarized and the Windows build is not code-signed.
