TrailForge v0.6.0, an off-road vehicle prototype on a small custom C++20 engine (SDL3 + SDL GPU, Jolt Physics
`WheeledVehicleController`, Dear ImGui, own audio mixer on miniaudio). This stage lays the groundwork for Windows
and Linux: one HLSL shader source compiled at build time for Metal, Vulkan and Direct3D 12, Windows and Linux build
presets, packaging scripts and GitHub Actions CI. Gameplay, physics, sound and the look on macOS are unchanged from
v0.5.0.

**Platforms:**

| Package | Status |
|---|---|
| `TrailForge-0.6.0-macos-arm64.zip` | macOS 27 on Apple Silicon. **Run and verified** (built for macOS 27.0). |
| `TrailForge-0.6.0-windows-x64.zip` | **UNTESTED ON REAL HARDWARE.** Built and headless-tested in GitHub Actions (MSVC, x64); the D3D12 / Vulkan rendering has never been run. |
| `TrailForge-0.6.0-linux-x64.tar.gz` | **UNTESTED ON REAL HARDWARE.** Built and headless-tested in GitHub Actions (gcc, Ubuntu); the app was only started on Mesa lavapipe (software Vulkan) under Xvfb, where it renders a correct frame without Vulkan validation errors. |

## What is new

- **One shader source for every backend.** `shaders/scene.hlsl` replaces the Metal-only shader. At build time each
  of its 23 entry points is compiled to SPIR-V (Vulkan) and, on macOS, to a Metal library; Windows builds also
  produce DXIL (Direct3D 12). The compiler toolchain (glslang, SPIRV-Tools, SPIRV-Cross, and DXC on Windows) is
  downloaded as pinned, checksummed archives like the other dependencies; nothing generated is committed.
- **The game picks the shader format the GPU driver accepts** (Metal library, then DXIL, then SPIR-V). The console
  prints it at start, e.g. `GPU driver 'metal', shaders: metallib (precompiled)`.
- **The macOS picture is the same as v0.5.0.** Each frame of the visual tour, time of day, grass and spray captures
  (38 frames at 2880x1800) was rendered with the old and the new shaders from the same game state: 0.0016 % of the
  pixels differ, almost all by 1 / 255. Frame times are unchanged (GPU time within the run-to-run spread; Ultra
  about 1 % higher).
- **GPU frame time** is shown on Metal as before and as `n/a` on other backends.
- **MSAA** picks the highest sample count the GPU supports at or below the preset's setting.
- `trailforge --paths` prints where the sounds are loaded from and the user data folder (reserved for future
  settings).

## How to open it

**macOS.** The app is **ad-hoc signed, not notarized**, so Gatekeeper blocks a plain double-click after downloading.

1. Unzip `TrailForge-0.6.0-macos-arm64.zip`.
2. Either right-click `TrailForge.app` → **Open** → **Open**, or remove the quarantine flag in Terminal:
   `xattr -dr com.apple.quarantine TrailForge.app`
3. Optional command-line options (run the binary inside the bundle):
   `TrailForge.app/Contents/MacOS/trailforge --help`

**Windows (untested on real hardware).** Unzip, keep the `assets` folder next to `trailforge.exe`, run it. The exe
is not code-signed, so SmartScreen may warn ("More info" → "Run anyway"). Needs a Direct3D 12 or Vulkan GPU driver.

**Linux (untested on real hardware).** `tar xzf TrailForge-0.6.0-linux-x64.tar.gz`, then
`./TrailForge-0.6.0-linux-x64/trailforge`. Needs a Vulkan driver (Mesa RADV / ANV / NVK or the NVIDIA driver).

If you try Windows or Linux, the most useful report is the console output and whether the picture looks like the
macOS screenshots (sky, shadows, grass, puddle reflections, nothing upside down). From a source checkout,
`trailforge --script tools/scenarios/full_check.txt --no-audio` runs the full scripted check (expect `0 failed`).

## Known limitations

- Windows and Linux have never been run on real hardware; the Direct3D 12 path has not been run at all.
- On Vulkan the shadow depth bias is not clamped (SDL does not enable that device feature), so shadows may differ
  slightly from Metal on steep surfaces. GPU frame time is only measured on Metal.
- The HLSL front end used for SPIR-V (glslang) is deprecated upstream; it works with the pinned version.
- macOS build not notarized; Windows build not code-signed.
- All v0.5.0 limitations still apply: grass, flowers and wheat are render-only and were judged from still captures;
  ABS and TC are simplified logic, "locked" differentials are a strong torque bias, the ground is rigid (sand and mud
  are lower-friction surfaces only), handling and sound have not been judged by hand or by ear, and gamepad support
  has not been tested with a real controller.
