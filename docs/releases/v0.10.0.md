TrailForge v0.10.0, an off-road vehicle prototype on a small custom C++20 engine (SDL3 + SDL GPU, Jolt Physics
`WheeledVehicleController`, Dear ImGui, own audio mixer on miniaudio). This stage adds a Controls page with a choice
of drive keys and drawn keyboard / gamepad diagrams, progressive keyboard pedals, tire sounds per vehicle, shorter
tire squeal and launch rubber marks that follow the wheelspin.

**Platforms:**

| Package | Status |
|---|---|
| `TrailForge-0.10.0-macos-arm64.zip` | macOS 27 on Apple Silicon. **Run and verified** (built for macOS 27.0). |
| `TrailForge-0.10.0-windows-x64.zip` | **UNTESTED ON REAL HARDWARE.** Built and headless-tested in GitHub Actions (MSVC, x64); the D3D12 / Vulkan rendering has never been run. |
| `TrailForge-0.10.0-linux-x64.tar.gz` | **UNTESTED ON REAL HARDWARE.** Built and headless-tested in GitHub Actions (gcc, Ubuntu); the app was only started on Mesa lavapipe (software Vulkan) under Xvfb. |

## What is new

- **Settings > Controls page.**
  - **DRIVE KEYS:** W A S D or the arrow keys. The cluster that does not drive moves the free camera. Saved in
    `settings.cfg` (`drive_keys`). The HUD, intro and pause hints follow the choice.
  - A vector keyboard diagram shows only the bound keys at their real positions. The drive keys are bold, and every
    key has a callout. Callouts never overlap: 0 overlaps measured in every layout and glyph combination. The mouse
    (orbit / zoom) is drawn too. Key caps use the names of the running platform: RETURN, DELETE, PAGE UP on macOS;
    ENTER, BACKSPACE, PG UP on Windows / Linux.
  - **GAMEPAD BUTTONS:** AUTO, XBOX or PLAYSTATION (`pad_glyphs`). AUTO picks the names from the connected pad's
    type (PS3 / PS4 / PS5 → PlayStation, everything else → Xbox). A drawn controller has a callout for every bound
    control, and a line shows whether a pad is connected.
  - Bindings, key names and glyph names live in one SDL-free module that is covered by unit tests.
- **Progressive keyboard pedals** (both drive layouts). W ramps to 0.5 in 0.15 s and to full after 0.8 s; S ramps
  to 0.4 in 0.1 s and to full after 0.7 s; both release instantly. Gamepad triggers are unchanged. Measured on the
  SUV in 2H on concrete (headless probe, instant → ramped):
  - held W: peak wheel slip 4.80 → 0.92 m/s, sliding time 2.23 → 0 s, rubber 0.77 → 0;
  - 0-30 km/h: 1.90 → 1.73 s;
  - 0.25 s tap on S at 50 km/h: peak slip 7.57 → 1.17 m/s, no rubber. A held S still locks the wheels, as before.
- **Tire sound per vehicle.** The SUV gets a darker, quieter squeal with a low scrub layer (spectral centroid 1048 Hz
  instead of 1473 Hz, -0.6 dB). Other vehicles keep the previous sound, and vehicle.json can override it.
- **Shorter, proportional tire squeal.** Measured on the SUV on concrete with the headless probe, before → after:
  - full-throttle launch: audible for 2.23 s → silent;
  - 0.25 s brake tap: audible for 1.81 s → silent;
  - 0.5 s brake tap: 1.82 s → 0.57 s;
  - a full stop's squeal now ends with the slide (it used to ring 0.53 s after it);
  - handbrake and power slides keep their level.
- **Launch rubber marks follow the wheelspin.** Marks build up with how much and how long a tire spins. Measured on
  the SUV on concrete:
  - full-pedal launch in 2H: darkest mark 0.76 → 0.16, width 0.32 → 0.11 m;
  - a normal pull-away leaves no marks (keyboard W, gentle throttle, 4H);
  - dark marks only come from multi-second burnouts.
  Lock-up and sideways marks are unchanged.

## How to open it

**macOS.** The app is **ad-hoc signed, not notarized**, so Gatekeeper blocks a plain double-click after downloading.

1. Unzip `TrailForge-0.10.0-macos-arm64.zip`.
2. Either right-click `TrailForge.app` → **Open** → **Open**, or remove the quarantine flag in Terminal:
   `xattr -dr com.apple.quarantine TrailForge.app`
3. Optional command-line options (run the binary inside the bundle):
   `TrailForge.app/Contents/MacOS/trailforge --help`

**Windows (untested on real hardware).** Unzip, keep the `assets` folder next to `trailforge.exe`, run it. The exe
is not code-signed, so SmartScreen may warn ("More info" → "Run anyway"). Needs a Direct3D 12 or Vulkan GPU driver.

**Linux (untested on real hardware).** `tar xzf TrailForge-0.10.0-linux-x64.tar.gz`, then
`./TrailForge-0.10.0-linux-x64/trailforge`. Needs a Vulkan driver (Mesa RADV / ANV / NVK or the NVIDIA driver).

## Known limitations

- Windows and Linux have never been run on real hardware; the Direct3D 12 path has not been run at all.
- No gamepad was connected during development. The gamepad diagram, the automatic Xbox / PlayStation choice with a
  real pad and the gamepad bindings were checked only through unit tests and a stand-in pad type in the scenario
  checks. Nintendo and other pads show Xbox names.
- The keyboard diagram is a US ANSI layout. Discrete action keys use the key's character, so on other layouts they
  may sit elsewhere than drawn. The drive clusters use physical key positions.
- Keys are not rebindable; only the drive cluster can be chosen.
- Tire sounds were judged from capture analysis, not by ear.
- macOS build not notarized; Windows build not code-signed.
- Earlier limitations still apply:
  - grass, spray and body mud are render-only;
  - ABS and TC are simplified logic;
  - the ground is rigid (sand and mud are lower-friction surfaces only);
  - the 4H / 4L center lock is a strong limited-slip setting.
