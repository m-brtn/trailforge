TrailForge v0.18.1, an off-road vehicle prototype on a small custom C++20 engine (SDL3 + SDL GPU, Jolt Physics
`WheeledVehicleController`, Dear ImGui, own audio mixer on miniaudio). This is a **fix-only re-release of v0.18.0**
(CC0 level models, reshaped canyon, animated waterfalls): the level bake read one sample past the end of the height
grid, which crashed the Windows build and was undefined behavior on every platform.

**Platforms:**

| Package | Status |
|---|---|
| `TrailForge-0.18.1-macos-arm64.zip` | macOS 27 on Apple Silicon. **Run and verified** (built for macOS 27.0). |
| `TrailForge-0.18.1-windows-x64.zip` | **UNTESTED ON REAL HARDWARE.** Built and headless-tested in GitHub Actions (MSVC, x64); the D3D12 / Vulkan rendering has never been run. |
| `TrailForge-0.18.1-linux-x64.tar.gz` | **UNTESTED ON REAL HARDWARE.** Built and headless-tested in GitHub Actions (gcc, Ubuntu); the app was only started on Mesa lavapipe (software Vulkan) under Xvfb, without loading the level. |

## What changed since v0.18.0

- **Height grid read past the end.** Sampling the terrain height exactly at the far edge of the level read one value
  past the height grid. The Windows build crashed while loading Exploration Peaks (all level tests failed in CI);
  macOS and Linux read a stray value without crashing. Found with AddressSanitizer; the level, core, vehicle and audio
  tests are now clean under AddressSanitizer and UndefinedBehaviorSanitizer on macOS.
- Everything else is as in v0.18.0: see the
  [v0.18.0 notes](https://github.com/m-brtn/game/releases/tag/v0.18.0) for the level models, canyon, waterfalls and
  the measured frame rates.

## How to open it

**macOS.** The app is **ad-hoc signed, not notarized**, so Gatekeeper blocks a plain double-click after downloading.

1. Unzip `TrailForge-0.18.1-macos-arm64.zip`.
2. Either right-click `TrailForge.app` → **Open** → **Open**, or remove the quarantine flag in Terminal:
   `xattr -dr com.apple.quarantine TrailForge.app`
3. Optional command-line options (run the binary inside the bundle):
   `TrailForge.app/Contents/MacOS/trailforge --help`

**Windows (untested on real hardware).** Unzip, keep the `assets` folder next to `trailforge.exe`, run it. The exe
is not code-signed, so SmartScreen may warn ("More info" → "Run anyway"). Needs a Direct3D 12 or Vulkan GPU driver.

**Linux (untested on real hardware).** `tar xzf TrailForge-0.18.1-linux-x64.tar.gz`, then
`./TrailForge-0.18.1-linux-x64/trailforge`. Needs a Vulkan driver (Mesa RADV / ANV / NVK or the NVIDIA driver).

## Known limitations

- Same as v0.18.0: Ultra misses 60 fps in the dense forest (37–48 fps); waterfalls seen from above still read as a
  flat white panel; water, sky and post effects are unchanged; the models add 84 MB to the download; nobody has judged
  the new world by eye beyond still captures.
- Windows and Linux have never been run on real hardware; the Direct3D 12 path has not been run at all.
- macOS build not notarized; Windows build not code-signed.
