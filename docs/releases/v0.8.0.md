TrailForge v0.8.0, an off-road vehicle prototype on a small custom C++20 engine (SDL3 + SDL GPU, Jolt Physics
`WheeledVehicleController`, Dear ImGui, own audio mixer on miniaudio). This stage moves the vehicle out of the
code into a data file, adds drivetrain layouts with a part-time transfer case (2H / 4H / 4L), and adds a garage
where the vehicle can be tuned and the setups saved.

**Platforms:**

| Package | Status |
|---|---|
| `TrailForge-0.8.0-macos-arm64.zip` | macOS 27 on Apple Silicon. **Run and verified** (built for macOS 27.0). |
| `TrailForge-0.8.0-windows-x64.zip` | **UNTESTED ON REAL HARDWARE.** Built and headless-tested in GitHub Actions (MSVC, x64); the D3D12 / Vulkan rendering has never been run. |
| `TrailForge-0.8.0-linux-x64.tar.gz` | **UNTESTED ON REAL HARDWARE.** Built and headless-tested in GitHub Actions (gcc, Ubuntu); the app was only started on Mesa lavapipe (software Vulkan) under Xvfb. |

## What is new

- **Vehicles are data.** The SUV is described in `assets/vehicles/trailforge_suv/vehicle.json` (chassis, per-axle
  suspension, wheels and tires, engine, gearbox, drivetrain, brakes, steering, aids, visuals, kits). The file is
  validated on load with readable errors. With the old full-time AWD layout it reproduces v0.7.0 exactly: all
  headless physics test outputs and probe measurements were byte-identical (for example 0-30 km/h on concrete in
  1.52 s, a stop from 50 km/h in 13.66 m).
- **Drivetrain layouts:** RWD, FWD, full-time AWD, part-time 4WD and on-demand AWD. An undriven axle gets no
  torque but still brakes.
- **The SUV now has a part-time transfer case** and starts in **2H** (rear-wheel drive). **V** cycles
  2H → 4H → 4L → 2H, **L** selects 4L. 4H and 4L lock the center; 4L only engages at a standstill. The HUD shows
  2H (dim), 4H (green) or 4L (amber). Measured with the headless probe: on concrete 0-30 km/h takes 1.97 s in 2H
  (with wheelspin) vs 1.52 s with the old AWD; in 2H the SUV cannot climb the 15° mud ramp (stops after 13 m of
  30 m), in 4H it tops it in 6.1 s.
- **Aerodynamic drag** (drag area 1.3 m², applied at the center of mass). Small effect at these speeds: speed after
  2 s on concrete 9.03 → 9.00 m/s.
- **Garage** (start menu and pause menu): base vehicle → kit → fine tune. Suspension (spring frequency,
  compression and rebound damping, preload, anti-roll bars, ride height), tires (grip scale, peak slip ratio and
  angle), engine (torque, rev limit, final drive), brakes (torque, front share), drivetrain (layout, front share,
  differentials) and aid thresholds. Most values change the running vehicle immediately; layout, preload and ride
  height rebuild it in place. Several setups per vehicle (save, save as new, rename, delete, reset to factory),
  stored in the user data folder (`trailforge --paths`) and restored at the next start.
- New vehicle features available to the data file: separate compression / rebound damping, bump stops, Ackermann
  steering, rev limiter, per-axle brakes and handbrake.

## How to open it

**macOS.** The app is **ad-hoc signed, not notarized**, so Gatekeeper blocks a plain double-click after downloading.

1. Unzip `TrailForge-0.8.0-macos-arm64.zip`.
2. Either right-click `TrailForge.app` → **Open** → **Open**, or remove the quarantine flag in Terminal:
   `xattr -dr com.apple.quarantine TrailForge.app`
3. Optional command-line options (run the binary inside the bundle):
   `TrailForge.app/Contents/MacOS/trailforge --help`

**Windows (untested on real hardware).** Unzip, keep the `assets` folder next to `trailforge.exe`, run it. The exe
is not code-signed, so SmartScreen may warn ("More info" → "Run anyway"). Needs a Direct3D 12 or Vulkan GPU driver.

**Linux (untested on real hardware).** `tar xzf TrailForge-0.8.0-linux-x64.tar.gz`, then
`./TrailForge-0.8.0-linux-x64/trailforge`. Needs a Vulkan driver (Mesa RADV / ANV / NVK or the NVIDIA driver).

## Known limitations

- Windows and Linux have never been run on real hardware; the Direct3D 12 path has not been run at all.
- The garage and the menus have not been tested with a real gamepad (keyboard and mouse were tested through the
  real input path in scripted runs). The garage was checked at one window size (2880x1800, 2x HiDPI).
- A "locked" center (4H / 4L) is a very strong limited-slip setting, not a rigid shaft: there is no driveline
  wind-up in tight turns on grippy ground. On-demand AWD is a center limited-slip differential, not a clutch with a
  controller.
- Compression / rebound damping reacts one physics tick late; bump stops are a stiffness ramp; Ackermann only
  limits the outer wheel; drag has no lift or pitch effect.
- Only one vehicle ships; kits are supported by the format but the SUV has no kit content yet. Tire "grip" and
  "slip" settings are not a tire pressure model.
- Handling has not been judged by hand; all numbers come from headless measurements and scripted runs.
- macOS build not notarized; Windows build not code-signed.
- Earlier limitations still apply: grass and spray are render-only, ABS and TC are simplified logic, the ground is
  rigid (sand and mud are lower-friction surfaces only).
